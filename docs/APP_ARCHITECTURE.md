# 颜值打分应用：组装框架与技术方案

## 1. 目标与边界

- 目标：把现有 Flet 单文件程序拆成可替换、可校准、可打包的应用，支持 SCUT、MEBeauty、众包三套权重独立演进。
- 输出：统一 1–10 分展示；内部允许模型输出原始分，再由 `calib.json` 做单调分位数映射。
- 运行：最终 EXE 使用 CPU 版 torch，`console=False`，onedir 分发；训练与评估使用 conda `py311` + CUDA。
- 非目标：当前不把众包标注表用于训练，等标注完成后单独跑第三路线；不改写数据集的绝对主观分数。

## 2. 总体架构

```text
Flet UI
  -> AppController（状态、进度、错误提示）
  -> InferenceEngine（模型注册、路由、集成）
  -> Preprocess（检测、对齐、裁切、质量门控）
  -> ModelAdapter（ResNetFusion 加载与推理）
  -> ScoreCalibrator（单调校准、置信度收缩、分数带）
  -> Diagnostics（原因码、置信度、可解释指标）
```

目录建议：

```text
app/
  config.py        # 路径、输入尺寸、阈值、模型清单
  preprocess.py    # 人脸检测、最大脸、滚转对齐、裁切
  features.py      # mediapipe 468 点 -> 14 维几何特征
  models.py        # ResNetFusion 与权重加载
  scoring.py       # 校准、集成、置信度、原因码
  engine.py        # 单图推理编排
  ui.py            # Flet 页面
weights/
  scut/best.pth + calib.json
  meb/best.pth + calib.json
  crowd/best.pth + calib.json
  manifest.json    # 版本、SHA256、输入尺寸、路由标签
```

保持 `new_main.py` 可用，先以适配层接入；拆模块完成并回归通过后再替换入口。

## 3. 推理链路

1. 读取图片，按最长边限制缩放到 `MAX_SIDE`，避免超大手机照片占满内存。
2. 用 mediapipe 检测所有人脸，选择面积最大的脸；无人脸直接返回可读错误。
3. 根据双眼关键点估计滚转，旋转对齐；按统一边距裁出正方形。
4. 质量门控：清晰度、亮度、遮挡、侧脸比例、脸部占比、姿态角。
5. 在“对齐裁切后”的脸图上提取 468 点，再转 14 维几何特征。
6. 图像 resize 到模型训练尺寸；当前新路线为 224，旧五折权重为 350。
7. 模型输出原始分；按权重对应的 `calib.json` 做单调映射。
8. 多模型按路线加权或路由；输出最终分、置信度、诊断原因和模型版本。

关键约束：训练和推理的几何特征必须来自同一套关键点定义。SCUT/MEBeauty 当前离线清单使用数据集自带 86/68 点，GUI 使用 mediapipe 468 点；生产权重优先使用统一 mediapipe 的众包路线，或后续重新预提 SCUT/MEBeauty 关键点后重训。

## 4. 模型仓库与路由

- `scut`：华工官方 1–5 均值 ×2，适合正脸、近景、无美颜的基准域。
- `meb`：MEBeauty 原生 1–10，跨种族、跨性别分布更广，适合真实网络人像。
- `crowd`：众包标注完成后训练，重点补侧脸、远景、美颜、磨皮、仰俯角。
- 路由优先使用显式域标签；无法判断时采用等权或按验证集误差反比加权。
- 低置信度输入不强行给极端分，向总体均值做有限收缩；收缩只作用于确认不可信的样本。
- 每次发布把权重、`calib.json`、`manifest.json` 的 SHA256 写入日志，支持回滚。

## 5. 分数映射与校准

- 数据集原标签不直接改写：SCUT 仍保留官方 1–5，清单中单调乘 2；MEBeauty 保留原生 1–10；众包保留聚合原始分。
- 训练阶段对分布尾部使用样本权重，避免 1–3 分和 8–10 分因样本少而完全学不到。
- 输出阶段使用验证集拟合单调分位数映射，把预测分布拉到目标先验；排序不变，只改变分数落点。
- 目标先验默认取 MEBeauty 的 KDE 分布；每条路线必须保存自己的 `calib.json`，不能混用。
- 推荐展示一位小数，并在内部保留原始分与校准分，便于审计和回归。
- 低置信度样本只做有限均值收缩，不把正常正脸强行压成 5–6 分。

## 6. 质量门控与异常输入

建议统一返回结构：`score`、`raw_score`、`confidence`、`reason_codes`、`face_box`、`pose`、`model_versions`。

- 无人脸：拒绝打分，提示“未检测到人脸”，不进入模型。
- 人脸过小或远景：降低置信度；若低于硬阈值则提示重拍，避免把全身照硬裁成模糊脸。
- 模糊、逆光、过曝：按清晰度与亮度评分降权，严重时拒绝。
- 侧脸：估计 yaw；轻度侧脸走众包路线，重度侧脸直接拒绝或只返回区间。
- 仰视/俯视：估计 pitch；在允许范围内按姿态做置信度校准，不允许直接套正脸高分。
- 美颜/磨皮：用高频纹理与皮肤平滑度作为诊断项；模型可打分，但必须降低置信度并提示“可能受美颜影响”。
- 遮挡：口罩、墨镜、手挡脸等检测到关键点缺失率过高时拒绝或降权。
- 所有拒绝都要有稳定原因码，UI 不直接展示底层异常字符串。

## 7. 与现有 GUI 的接入约束

- 新路线输入尺寸为 224：接入新权重时把 `INPUT_SIZE` 从 350 改为 224。
- 新路线输出已经是 1–10：把 `DISPLAY_SCALE` 从 2.0 改为 1.0，避免二次乘 2。
- 旧五折 350 权重与新华工/MEB/众包权重不能在同一次推理中混用不同尺寸或不同缩放。
- 生产切换前保留旧 `resnetfusion_fold*_best.pth` 与旧 `calib.json`，用配置开关回滚。
- 迁移顺序：先复制预处理与质量门控到 `app/`，再接单模型，最后接多模型路由；每步都做同一组回归图片。

## 8. 打包与进程生命周期

- 训练环境：conda `py311` + `torch 2.9.1+cu128`，通过 `PYTHONPATH=D:\torch_cu128_backup\site-packages` 启用 GPU；仅用于训练和评估。
- 分发环境：同一 conda 环境切回 CPU 版 torch，PyInstaller `onedir`，`console=False`，带 `app.ico`。
- `mediapipe`、`scipy`、MKL/BLAS DLL 必须显式收集；中文安装路径要在发布前实测。
- Flet 会拉起 `fletd.exe` 子进程。退出时必须关闭页面、等待子进程结束；异常退出后由启动器清理残留，避免僵尸进程累积。
- 启动时设置 `NO_ALBUMENTATIONS_UPDATE=1`、`GLOG_minloglevel=2`，禁止联网版本检查和 mediapipe INFO 日志。
- EXE 目录保持纯英文或提供中文路径兼容处理；训练脚本建议也迁到纯英文根目录，降低 Windows 多进程与 C++ 资源加载风险。

## 9. 验收标准

- 主验收口径：`hit@0.2 = mean(|预测分 - 真值| <= 0.2)`，同时记录 `hit@0.5` 与 `hit@1.0` 作为辅助。
- 主指标不达标时不得通过改阈值、只报相关系数或只报训练集结果来放行。
- 功能：无人脸、远景、侧脸、仰俯角、磨皮、美颜、多人合照均有确定行为，不崩溃。
- 分布：测试集分数覆盖 1–10；2–3 分与 8–10 分不再恒为空；5–6 分具有可区分排序。
- 排序：校准前后 Spearman 不变；各路线报告 MAE、RMSE、Pearson、Spearman、斜率与预测标准差。
- 稳健性：同一人轻度旋转、压缩、亮度变化后分数波动受限；重度退化输入置信度显著下降。
- 性能：CPU 单图 P95 目标小于 2 秒；内存峰值可控；连续处理 50 张无进程泄漏。
- 打包：离线机器可启动、可推理、无控制台窗口、无联网等待、退出后无残留进程。

## 10. 实施顺序

1. P0：完成 SCUT 与 MEBeauty 两条 GPU 训练，比较原始与校准指标。
2. P1：众包标注完成后构建 `crowd` 清单，统一 mediapipe 468 点后训练第三路线。
3. P2：实现 `app/` 单模型推理与质量门控，完成三条路线离线回归。
4. P3：加入路由/集成、置信度与原因码，接入 Flet 新界面。
5. P4：CPU 版 PyInstaller 打包，中文路径、离线、连续推理和退出清理验收。

当前不把仍在增长的众包标注表纳入训练；等标注冻结后再跑第三路线，避免标签版本漂移。
